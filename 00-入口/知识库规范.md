# 知识库规范

## YAML 元数据规范

所有笔记（00-09 目录下）的 frontmatter 必须包含以下字段，Codex 才能可靠地按 `status` / `version` 过滤：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `title` | 必填 | 任意字符串 | 笔记标题 |
| `type` | 必填 | function / workflow / parameter / troubleshooting / example / index（兼容旧值：concept / reference / error / note） | 内容类型，与模板对应 |
| `status` | 必填 | `draft` / `source` / `verified` / `deprecated` / `conflict` | 可信度：未验证草稿 / 依原文整理 / 已实践验证 / 已废弃 / 存在冲突 |
| `version` | 必填 | 如 `2024` | 适用 Crosslight 版本 |
| `source` | 必填 | 指向 `99-原始资料/` 的原文（wiki 链接或路径） | 占位/索引笔记用 `-` |
| `last_verified` | 必填 | `YYYY-MM-DD` | 最近一次核对日期 |

约束：

- 不同版本参数不得混用；
- 不确定的内容必须标注（`status: draft` 或正文注明"未验证"）；
- 生成配置前先检查参数约束；
- 不得编造命令、参数或输出。

## 模板

`_templates/` 下 4 个模板的定位关系：

```text
功能说明模板  → 回答"这是什么"      （type: function，产品/模块/工具）
操作流程模板  → 回答"怎么做"        （type: workflow，任务步骤，全库核心）
API参数模板   → 回答"参数怎么用"    （type: parameter，单个参数细节）
故障排查模板  → 回答"出错怎么办"    （type: troubleshooting，错误现象 → 根因 → 修复）
```

- `_templates/功能说明模板.md`
- `_templates/操作流程模板.md`
- `_templates/API参数模板.md`
- `_templates/故障排查模板.md`

模板中的 `{{title}}` / `{{date}}` 由 Obsidian「插入模板」时自动替换；`<!-- 注释 -->` 是填表指引，填写时删除；`> [!warning]` 是警示框，保留。

Obsidian「设置 → 模板」的模板文件夹位置指向 `_templates/`（配置见 `.obsidian/templates.json`）。

## 完整性检查

```bat
python scripts/check_notes.py .
```

脚本检查：frontmatter 六字段是否齐全、status 取值是否合法、命令是否在代码块内、双链目标是否存在。输出 `0 errors` 才可提交。
