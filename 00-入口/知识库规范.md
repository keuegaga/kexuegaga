# 知识库规范

## YAML 元数据规范

所有笔记（00-09 目录下）的 frontmatter 必须包含以下字段，Codex 才能可靠地按 `status` / `version` 过滤：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `title` | 必填 | 任意字符串 | 笔记标题 |
| `type` | 必填 | function / workflow / parameter / troubleshooting / example / index（兼容旧值：concept / reference / error / note） | 内容类型，与模板对应 |
| `status` | 必填 | `draft` / `source` / `verified` / `deprecated` / `conflict` | 可信度：未验证草稿 / 依原文整理 / 已实践验证 / 已废弃 / 存在冲突 |
| `version` | 必填 | 如 `2024` | 适用 Crosslight 版本 |
| `source` | 必填 | 指向 `99-原始资料/` 的原文（wiki 链接或路径） | 占位/索引笔记用 `-` |
| `last_verified` | 必填 | `YYYY-MM-DD` | 最近一次核对日期 |

约束：

- 不同版本参数不得混用；
- 不确定的内容必须标注（`status: draft` 或正文注明"未验证"）；
- 生成配置前先检查参数约束；
- 不得编造命令、参数或输出。

## 模板

`_templates/` 下 4 个模板的定位关系：

```text
功能说明模板  → 回答"这是什么"      （type: function，产品/模块/工具）
操作流程模板  → 回答"怎么做"        （type: workflow，任务步骤，全库核心）
API参数模板   → 回答"参数怎么用"    （type: parameter，单个参数细节）
故障排查模板  → 回答"出错怎么办"    （type: troubleshooting，错误现象 → 根因 → 修复）
```

- `_templates/功能说明模板.md`
- `_templates/操作流程模板.md`
- `_templates/API参数模板.md`
- `_templates/故障排查模板.md`

模板中的 `{{title}}` / `{{date}}` 由 Obsidian「插入模板」时自动替换；`<!-- 注释 -->` 是填表指引，填写时删除；`> [!warning]` 是警示框，保留。

Obsidian「设置 → 模板」的模板文件夹位置指向 `_templates/`（配置见 `.obsidian/templates.json`）。

## 文件编码规范（Crosslight 原生 GUI 可读）

被 Crosslight 原生 GUI（SimuPics3d / SimuCenter / LayerBuilder / GeoEditor 等）打开的文件，注释**不得使用 UTF-8 无 BOM**：

| 文件 | 编码要求 | 理由 |
|---|---|---|
| `.sol` / `.layer` / `.geo` / `.gain` / `.mater` 等输入文件 | **纯 ASCII（首选）或 GBK（CP936）** | 原生 GUI 按系统 ANSI 代码页解码；UTF-8 中文会显示成 `鏂囦欢` 这类乱码（实测：SimuPics3d 2024） |
| Obsidian 笔记 `.md` | UTF-8（无 BOM） | 只由 Obsidian / 编辑器打开，不受影响 |
| PowerShell 脚本 `.ps1`（含中文） | **UTF-8 with BOM**；且**输出字符串写成 ASCII**，中文只留在注释里 | Windows PowerShell 5.1 对**无 BOM** 的文件按 ANSI(GBK) 解码，会直接抛语法错误（实测：`意外的标记"鐢垫祦宸茶揪"`）。脚本文件本身写 BOM，同时把字符串做成 ASCII，这样即使 BOM 被编辑器弄丢也不会挂 |

规则：

- 生成或修改用户要上机的输入文件时，**注释优先写纯英文（ASCII）**；确需中文时把文件存为 **GBK**；
- **不要用 UTF-8 with BOM**：`.sol` 首行是 `$` 注释，BOM 可能让解析器把首行当成未知语句报错；
- 编码不影响求解结果——`$` 之后整行都是注释；GBK 的次字节范围（0x40–0xFE）不含 `$`（0x24），不会被误判为注释符。
- **`.ps1` 相反**：必须带 BOM（PowerShell 5.1 需要），并且尽量不放非 ASCII 字符串。保存后可用下列命令核对：

```powershell
$p = 'D:\Codex-Obsidian\GaN-laser-pics3d\scripts\pics3d_watch_stop60.ps1'
([System.IO.File]::ReadAllBytes($p)[0..2] | ForEach-Object { '0x{0:X2}' -f $_ }) -join ' '   # 应为 0xEF 0xBB 0xBF
```

### `.plt` 报 `input file error: It does not contain one of the beginning statements`

**2026-09-16 实测真因：算例目录里那份 `.plt` 是 0 字节空文件。** 空文件里当然没有 `begin_pstprc`，于是报：

```text
input file error:
It does not contain one of the beginning statements:
begin, begin_gain, begin_pstprc, begin_rtgain, begin_bpmplot
```

教训：当时一度怀疑是换行符（LF/CRLF）、注释头里的中文、或起始语句位置，连着改了两轮仍报同一错误——**最后用 `Get-Item` 看文件大小（0 字节）才找到真因**。踩这个坑的原因是：`Copy-Item` 的源路径里含**中文目录名**（`06-案例`），在控制台被转码后**静默产生了空文件**。

排查顺序（按这个来，别再猜编码）：

1. `Get-Item .\xxx.plt | Select-Object Name, Length` —— **先看大小**；0 字节就是复制失败；
2. 复制路径含中文时，用**通配符避开中文**：

```powershell
Copy-Item 'D:\Codex-Obsidian\GaN-laser-pics3d\06-*\nakamura_analysis.plt' $d -Force
Get-Item "$d\s2.plt" | Select-Object Name, Length      # 复制后必须再核对
```

3. 万能兜底（绕开路径与编码的一切问题）：

```powershell
[IO.File]::WriteAllBytes($dst, [Convert]::FromBase64String('<base64 字符串>'))
```

补充：官方手册 P75 的用法是 `pics3d test1.plt`，**文件基名要与 `.sol`/`.out` 一致**；随后 `psplot test1.ps` 渲染（2024 安装里没有 `psplot.exe`，所以用 `plot_device=pdf` 或直接用 CrosslightView 看图）。把 `.plt` 保持**纯 ASCII + CRLF、`begin_pstprc` 放第 3 行**仍是好习惯（与官方 `s2.plt` 同构），但它并不是本次报错的原因。

UTF-8 → GBK 转换（实测可用）：

```powershell
$p = 'C:\path\to\file.sol'
$txt = Get-Content -LiteralPath $p -Raw -Encoding UTF8
[System.IO.File]::WriteAllText($p, $txt, [System.Text.Encoding]::GetEncoding(936))
```

转换后 VSCode 侧若显示乱码：右下角编码 → `Reopen with Encoding` → **GB18030**，或开启 `"files.autoGuessEncoding": true`。

### PowerShell 重定向出来的日志是 **UTF-16**（解析脚本必须先认 BOM）

2026-09-19 踩到：`s2_run.log` 用 PowerShell 的 `>` / `Select-Object *> file` 重定向生成，
**内容是 UTF-16LE + BOM**（文件头 `FF FE`）。用 UTF-8 或 GBK 去读，正则**全部静默失配**
（例如 `wavel=` 一条都搜不到），而 PowerShell 的 `Get-Content`/`Select-String` 会自动识别，
所以"PowerShell 里能看到、Python 里搜不到"。

**读日志的正确姿势**：

```python
raw = open(path, 'rb').read()
if raw[:2] in (b'\xff\xfe', b'\xfe\xff'):
    text = raw.decode('utf-16')      # PowerShell 重定向
else:
    text = raw.decode('utf-8-sig', errors='replace')
```

本库的 `scripts/pics3d_li_fit.py` 已内置这个判断。

**写脚本的规矩**：脚本自身的 `print` 输出**只用 ASCII**（控制台是 GBK 代码页，中文会变乱码），
中文解释放在笔记里。
